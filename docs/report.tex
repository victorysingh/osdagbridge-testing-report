\section{Summary}
I tested OsdagBridge (plate girder bridge module, \texttt{dev} branch, commit \texttt{d74f56d}) with 29 test cases and 6 consecutive design runs, using default values and custom values for the steel girders, stiffeners, bracing, end diaphragms and the concrete deck. 12 cases passed, the rest found problems. Input validation, repeatability across restarts, and the grade and deck propagation for girder and deck work correctly. The main problems are that several user inputs are not used or are reset (Save Input, Defaults button, bracing and end-diaphragm grade and section, limit-state ticks), that load combination factors are not applied, and that the report contradicts itself.

I posted \textbf{3 new GitHub issues} (\href{https://github.com/Nidhikhare12/OsdagBridge/issues/221}{\#221}, \href{https://github.com/Nidhikhare12/OsdagBridge/issues/222}{\#222}, \href{https://github.com/Nidhikhare12/OsdagBridge/issues/223}{\#223}), each with trigger conditions, evidence, root cause with file and line, and a suggested fix. For bugs that were already reported by others I did not open duplicates; I added \textbf{8 comments} with extra evidence and root cause to \href{https://github.com/Nidhikhare12/OsdagBridge/issues/174}{\#174}, \href{https://github.com/Nidhikhare12/OsdagBridge/issues/71}{\#71}, \href{https://github.com/Nidhikhare12/OsdagBridge/issues/146}{\#146}, \href{https://github.com/Nidhikhare12/OsdagBridge/issues/43}{\#43}, \href{https://github.com/Nidhikhare12/OsdagBridge/issues/216}{\#216}, \href{https://github.com/Nidhikhare12/OsdagBridge/issues/65}{\#65}, \href{https://github.com/Nidhikhare12/OsdagBridge/issues/115}{\#115} and \href{https://github.com/Nidhikhare12/OsdagBridge/issues/116}{\#116}. I checked all 136 existing issues and 84 pull requests before posting.

\section{Environment and method}
\begin{itemize}[nosep]
\item Windows, conda environment \texttt{osdagbridge-env}, started with \texttt{python -m osdagbridge.desktop} from \texttt{src}. Source: fork of \texttt{Nidhikhare12/OsdagBridge}, branch \texttt{dev}, commit \texttt{d74f56d}.
\item Defaults unless stated: Pehalgam (J\&K), no median, no footpath, Optimized design type, steel E~350A, deck M40.
\item Each design run produced a PDF design report and, where stated, a saved \texttt{.osi} input file (folders \texttt{reports/} and \texttt{osi\_files/} in the repository).
\item Checks: (1) compare the UI values with the saved input file and with the report; (2) compare numbers between runs that differ in one input; (3) hand calculations (section areas, utilisation ratios, load sums); (4) read the source code to find the cause of each failure.
\end{itemize}

\subsection*{The three new issues in short}
\textbf{\href{https://github.com/Nidhikhare12/OsdagBridge/issues/221}{\#221} Custom bracing section ignored (F24).} \texttt{crossbracingforces.py} (\texttt{run\_member\_designs}, about lines 619--626) copies the template dictionary \texttt{design\_dict\_tension\_bolted} / \texttt{design\_dict\_struts\_bolted} from \texttt{core/utils/connect.py} (lines 130 and 376) and changes only load and length. The template hard-codes material E~250 and the full angle list, so Osdag picks the lightest passing angle (40$\times$40$\times$3). The same pattern is in \texttt{plategirderbridge.py} (about lines 2762--2778). Fix: put the user's section into \texttt{Member.Designation} for Custom mode and the user's grade into \texttt{Material}.

\textbf{\href{https://github.com/Nidhikhare12/OsdagBridge/issues/222}{\#222} Defaults button (F30).} In \texttt{additional\_inputs.py}, \texttt{reset\_active\_tab\_defaults} (about line 446) restores from \texttt{default\_input\_dict}, which is the same object as the main \texttt{input\_dict} (line about 223) and is overwritten by \texttt{\_save\_inputs} (line about 519). Fix: keep a deep copy of the factory defaults; remove the leftover \texttt{pprint} (lines about 158--161).

\textbf{\href{https://github.com/Nidhikhare12/OsdagBridge/issues/223}{\#223} Stale section properties in the saved file (F26).} G2--G4 areas equal the empirical default section (0.01559201 m$^2$) instead of the entered one (hand: 0.020248 and 0.021328 m$^2$); G1 is saved as a 3-digit string; \texttt{web\_depth} is wrong. Fix: recompute properties for every girder before saving and store floats.

\section{Limitations and work not done}
\begin{itemize}[nosep]
\item I compared the Input Dictionary with the UI values and the reports in detail (section above). I did not compare every field of the Output Dictionary with the report and the Output Dock; I checked the cross-bracing forces, section properties and the load-case results only.
\item The deck design tables (Tables 5.16--5.22) were not hand-checked.
\item F1 (skew plots) and F10 (stiffener preview) are documented here but their root cause is not traced, so no issue was posted. F16 and F17 (double-angle properties) need further verification.
\item The saved \texttt{.osi} files cannot hold the custom deck, stud, $\gamma$ and tick values because of F28. These values are shown by the reports and in the screen recording instead.
\item Clear cover $=0/300$ and negative or text $\gamma$ values were not tested.
\end{itemize}
